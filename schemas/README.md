# schemas/ — the coordination surface

Owner: **Architecture Agent** (`agents/architecture.md`) — arbiter for all
changes here. Single source of contracts (Rule R1: schemas change first, code
second). Other agents propose changes via PR.

Seeded by task 0.2 (placeholder previously created by task 0.1, DevOps).

| Path | Contract | Consumers |
|---|---|---|
| `openapi/qds.yaml` | QDS read API (OpenAPI 3.1) | Backend qds, api-client, contract tests |
| `events/*.json` | Event envelope + per-type payloads (JSON Schema 2020-12) | API contexts, speech worker |
| `packs/manifest.schema.json` | `.qpack` manifest | pack-builder, clients' pack reader |
| `licenses.json` (+ `licenses.schema.json`) | Third-party dataset licensing registry (§6.4) | CI license check, About screen |

Rules:

- Every change gets an entry in `CHANGELOG.md` with a consumer-migration note
  (a schema change without one is an automatic reject).
- Event payloads are versioned via `schema_version`; breaking payload changes
  bump it and keep the old version consumable during migration (ICP).
- TypeScript types are generated by `tools/codegen` into
  `packages/api-client/src/generated/`; CI fails when generated types are stale.
  Regenerate with `pnpm --dir tools/codegen generate`.
